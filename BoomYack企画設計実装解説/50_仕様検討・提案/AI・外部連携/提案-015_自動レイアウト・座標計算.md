# 提案-015: 自動レイアウト・座標計算戦略

## 1. 現状
- AIが生成したノードデータには、通常「論理的な繋がり」のみが含まれ、「物理的な座標(x,y)」が含まれない。
- 座標が (0,0) に重なって生成されると、ユーザーが手動でバラす手間が発生する。

## 2. 問題点・課題
- **手間の増大**: AIに自動生成させても、整頓の手間が生成のメリットを上回ってしまう恐れがある。
- **視認性**: 重なったノードは読めない。

## 3. 提案内容
AI生成時、またはユーザーの指示により、ノードの適切な座標を計算し適用する。

### 3-1. 解決策案
#### 案A: Frontend Layout (Dagre / Force-Directed)
- クライアント側で `dagre` や `d3-force` 等のライブラリを用いて計算する。
- **メリット**: インタラクティブな動きが作れる。
- **デメリット**: 既存の手動配置を崩さないように部分適用するのが難しい場合がある。

#### 案B: Server Calculation (Graphviz / NetworkX)
- サーバー側でPythonの強力なグラフライブラリ (`NetworkX`, `PyGraphviz`) を使って計算し、座標付きJSONを返す。
- **メリット**: 重い計算をサーバーに寄せられる。AI生成パイプラインに組み込みやすい。

#### 案C: Simple Offset (暫定対応)
- 親ノードの右側や下側に、一定のオフセットとランダムな分散を加えて配置する。
- 衝突判定を行い、空いているスペースを探す。

### 3-2. 推奨アプローチ
まずは **案C (Simple Offset)** から始め、**案A (Client Dagre)** の部分適用へとステップアップする。
`GraphExpansionService` は生成時に「親ノードの位置」を知っている必要があるため、リクエスト時に親座標を含める。

## 4. 影響範囲
- Server: 生成ロジックに座標計算ステップを追加。
- Client: ノード追加時のアニメーション等。

## 5. 課題
- 既存の「手動配置の良さ（意味のある配置）」を破壊しないこと。「完全自動整列」だけでなく「選択部分のみ整列」が重要。

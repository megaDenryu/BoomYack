# 提案-012: グラフ拡張生成機能 (AI続きを書いて)

## 1. 現状
- ユーザーが手動でノードを追加・接続する必要がある。
- AIによる自動化は一切ない。

## 2. 問題点・課題
- **思考のボトルネック**: アイデア出しや構造化の際、手動操作が思考のスピードに追いつかない。
- **AI活用**: 「このトピックについてもっと詳しく展開して」といった抽象的な指示を実現できない。

## 3. 提案内容
選択したノードを起点として、AIが文脈を読み取り、後続のグラフ（ノードとエッジ）を自動生成・接続する機能。

### 3-1. ユーザー体験 (UX)
1. GUI上でノードを選択。
2. コンテキストメニューまたはショートカットで「AI続きを書いて (Expand)」を実行。
3. (ローディング表示)
4. 起点ノードから伸びる形で、複数の新しいノードとエッジが出現する。

### 3-2. 処理フロー
1. **Request**: `client -> server`: `{ targetNodeId: "...", contextDepth: 2 }`
2. **Context Build**: サーバー側で、対象ノードの親・兄弟ノードのテキストを収集。
    - `GraphContext` 値オブジェクトに格納。
3. **Prompting**: LLM (OpenAI/Claude等) にプロンプト送信。
    - 「あなたは思考整理アシスタントです。以下の文脈に続くノードをJSONで出力してください」
4. **Validation**: 返却されたJSONがスキーマに適合するかチェック（Pydantic利用）。
5. **Merge**: 既存グラフデータとマージ。IDの衝突回避。
6. **Notify**: ファイル更新通知 -> クライアント反映。

### 3-3. クラス設計案 (DDD)
- `GraphExpansionService`: アプリケーションサービス。全体の調整役。
- `IAIGraphGenerator`: AIとの通信担当（Repositoryパターン）。
- `GraphContext`: 文脈情報を保持するValue Object。

## 4. 影響範囲
- Server: 新規実装の核となる部分。
- Client: UIへのトリガー追加。

## 5. 課題
- **座標**: AIは座標を出力できないため、後述の「自動レイアウト」との組み合わせが必須。

## ワークフロー

```
新規作成 → Draft/ → (承認・実装開始) → InProgress/ → (全Phase完了) → Done/
```

各ステップの定義:
- **Draft/**: 検討中・未承認。実装に入っていない提案
- **InProgress/**: 承認済み・実装中。部分完了（Phase途中）も含む
- **Done/**: 全Phaseが完了しコミット済みの提案

## 提案書フォーマット

```yaml
---
type: Proposal
status: Draft | InProgress | Done
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```

各提案書には以下のセクションを含める:
1. **現状** (Current State) — 変更前の状態
2. **問題点** (Problem / Motivation) — なぜ変える必要があるか
3. **提案内容** (Proposed Solution) — Phaseに分割した実装計画
4. **実装進捗** (Implementation Progress) — 各Phaseの完了状況 ← Phase完了ごとに更新
5. **影響範囲** (Impact) — 変更対象ファイルとリスク
6. **代替案** (Alternatives) — 採用しなかった案と理由

# 提案-020: AI生成・分解機能のUIバインディング（引き金の実装）

## 1. 概要
サーバー側に実装済みの「AIグラフ拡張（提案-012）」「ノード分解（提案-013）」ロジックを、フロントエンドのキャンバス上の付箋UIに接続（バインディング）し、ユーザーが実際にブラウザ上から使用できるようにする提案です。

## 2. 現状と課題（As-Is）
- バックエンドには `/BoomYack/AI/Generate` や `/BoomYack/Decomposition` といったエンドポイントが用意され、LLM（Gemini）への接続や意味的分割のロジックも構築済みです。
- しかし、キャンバス上の付箋UI（`自動リサイズ付箋View2.ts` やそのコンテキストメニュー）には、これらを呼び出すための**「AIによる続き生成ボタン」**や**「長文テキストの自動分割ボタン」**などの「引き金」となるUIが存在しません。
- 仕様書（`10_実装済み機能仕様/AI連携仕様.md`）ではこれらが「実装済み」と読める記載になっていますが、機能全体の結合テストや画面での動作確認が行えない状態です。

## 3. 提案（To-Be）
1. **API連携クライント**: フロントエンドから上記のAIサーバー機能を呼び出すための `AiApiRepository.ts` を新設し、FastAPIとの通信基盤を整えます。
2. **UI拡張（引き金）**: `自動リサイズ付箋View2.ts` のホバーメニュー（コンテキストメニューコンテナ内）に、以下の専用アクションボタンを追加します。
    - `[✨ 続きをAIに生成させる]`（提案-012）
    - `[✂️ 長文をノード分解する]`（提案-013）
3. **状態管理の統合**: 提案-012の `03_UI状態遷移・SengenUI実装設計.md` で設計したステートマシン（Draft状態、ローディングアニメーション）をフロントエンド上で動かし、APIからの通信を待つ間のUX（ローディングや仮配置の表現）を実装します。

## 4. 影響範囲
- `app-ts/src/BoomYack/基本オブジェクト/配置物/付箋2/自動リサイズ付箋View2.ts`
- `app-ts/src/BoomYack/基本オブジェクト/キャンバス操作/円状コンテキストメニュー/` 配下
- フロントエンドのAPI通信周りのコード（`AiApiRepository.ts` の新規作成）

## 5. 代替案と推奨
サーバー側のコードが揃っている今、一番のボトルネックは「UIとサーバーの未接続」による体験の欠如です。本提案を最優先で実施し、まずは「動くもの」を見ながらPromptや体験（UX）の改善サイクルを回すことを推奨します。

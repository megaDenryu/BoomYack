# 提案-020: AI生成・分解機能のUIバインディングおよびUI分離・エラーハンドリング改善

## 1. 概要
サーバー側に実装済みの「AIグラフ拡張（提案-012）」「ノード分解（提案-013）」ロジックを、フロントエンドのキャンバス上の付箋UIに接続（バインディング）し、ユーザーが実際にブラウザ上から使用できるようにする提案です。
さらに、分解機能においてLLM分解と区切り文字分解のUIを分離し、自動フォールバックを廃止してエラー通知（トースト）による明確なハンドリングへの改善も含みます。

## 2. 現状と課題（As-Is）
- バックエンドには `/BoomYack/AI/Generate` や `/BoomYack/Decompose` などのエンドポイントが用意され、LLMによる意味的分割ロジックも構築済みです。
- キャンバス上の付箋UIには、これらを呼び出すための「引き金」となるUIが存在せず、ブラウザ上から使用できません。
- また、現在の分解機能では、LLM分解に失敗した場合に自動的に「区切り文字分解」へ切り替わる（フォールバック）仕様となっており、挙動が不明瞭で意図しない分解結果を招く可能性があります。（区切り文字分解も区切り文字が存在しなければ失敗するため、自動フォールバックは無意味なケースがあります）

## 3. 提案（To-Be）
1. **API連携クライント**: フロントエンドからAIサーバー機能を呼び出すための `AiApiRepository.ts` などを整備します。
2. **UI拡張（引き金）**: `自動リサイズ付箋View2.ts` などのコンテキストメニューに、分離した専用アクションボタンを追加します。
    - `[✨ 続きをAIに生成させる]`
    - `[🧠 LLMでノードを意味分解する]`
    - `[✂️ 区切り文字でノードを分解する]`
3. **自動フォールバックの廃止とトースト通知**:
    - 各々の分解処理が失敗した場合、バックグラウンドでの自動再試行（フォールバック）は行わず、「トースト通知（画面上のエラーメッセージ）」を出して処理を終了する仕様とします。
    - フロントエンドから明示的に分解戦略名（`意味クラスタ` or `文単位`）を指定してAPIを呼び出します。
4. **状態管理の統合**: ローディングUXなどのステートマシンを統合し、API通信待ちUXを整備します。

## 4. 影響範囲
- `app-ts/src/BoomYack/基本オブジェクト/配置物/付箋2/自動リサイズ付箋View2.ts`
- `app-ts/src/BoomYack/基本オブジェクト/キャンバス操作/円状コンテキストメニュー/` 配下
- フロントエンドのAPI通信周りのコード（`AiApiRepository.ts` などの整備やトースト呼び出しの追加）
- バックエンドのAPIフォールバック処理の無効化、またはフロントエンドからの明示的コントロールへの対応

## 5. 次のステップ
- UIとサーバーの接続（API連携実装）、およびボタン分離等のUX改善を同時に行い、結合テストを実施する。

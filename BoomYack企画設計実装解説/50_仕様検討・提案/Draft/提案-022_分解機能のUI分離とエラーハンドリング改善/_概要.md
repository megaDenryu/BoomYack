# 提案-022: 分解機能のUI分離とエラーハンドリング改善

## 1. 概要
付箋を右クリックして実行する「分解機能」について、LLM分解と区切り文字分解のエンドポイントをUI上で明確に分け、暗黙の自動フォールバックを廃止する提案です。

## 2. 現状と課題（As-Is）
- 現在、分解ボタンを押すと「LLM分解」が走り、それに失敗した場合は自動的に「区切り文字分解」に切り替わる（フォールバックする）仕様になっている。
- ユーザーにとって自動フォールバックは挙動が不明瞭（微妙）であり、意図しない分解結果を招く。
- 区切り文字分解も、対象の区切り文字が存在しない場合はやはり失敗するため、フォールバックしても無意味なケースがある。

## 3. 提案（To-Be）
- **UIボタンの分離**: 
  - コンテキストメニュー内に「LLM分解ボタン」と「区切り文字分解ボタン」の2つを独立して設ける。
- **自動フォールバックの廃止とトースト通知**:
  - 各々の分解処理が失敗した場合、バックグラウンドでの自動再試行（フォールバック）は行わず、単に**「トースト通知（画面上のエラーメッセージ）」を出して**処理を終了する仕様とする。

## 4. 影響範囲
- コンテキストメニューUIの実装（ボタンの追加）
- フロントエンド側の分解API呼び出しロジック（フォールバック除去、トースト呼び出し）
- `api/BoomYack/Domain/ノード分解サービス.py` 側の実装の整理（もしバックエンドでフォールバックをやっているならUI側の指示に従うよう修正・もしくはAPI分離）

## 5. 次のステップ
- バックエンドのAPIがどのようにフォールバックを行っているか（既存仕様）を廃止し、フロントエンドから明示的に分解戦略名（`意味クラスタ` or `文単位`）を指定して呼び出し、エラー時にはTypeScript側でエラーハンドリングを行うよう改修。

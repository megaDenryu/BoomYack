# 提案-021: コンテキストメニューUIの改善_バームクーヘン型多段配置

## 1. 概要
コンテキストメニュー（ノード周辺に表示されるボタン群）において、長文のテキストが収まるように面積を確保するための「バームクーヘン型多段配置UI」を導入する提案です。

## 2. 現状と課題（As-Is）
- 現在のコンテキストボタンはサイズが小さく、長い文字を入れるとテキストがはみ出したり読めなかったりする。
- ボタンを単に円状に配置するだけでは面積が稼げず、長い項目名（「区切り文字分解」など）を視認性良く表示できない。

## 3. 提案（To-Be）
- **多段バームクーヘン型・レイアウト**:
  - 中心ノードを7x7などの「四角いマス目（CSS Grid）」のレイヤー構造で取り囲み、重なりを物理的に排除して広い面積を持たせる。
- **2つの表示パターン実装**:
  - **パターンA（常時表示型）**: 2階層目（各機能の詳細・長文ボタン）も最初から全て開きっぱなしにするモード。
  - **パターンB（クリック・入れ子展開型）**: 最初は1階層目の大枠ボタンのみ表示し、1階層目のボタンを**クリック**することで入れ子として2階層目のサブメニューが展開されるモード（※ホバーではなくクリックで操作状態を固定することで誤操作を防ぐ）。

## 4. 設計のアプローチ（具体化）
「バームクーヘン型」という抽象的概念を、SengenUI（HTML/CSS）上で安全に実現するため、**CSS Gridによる「多段グリッドコンテキストメニュー」**として再定義しました。

- **レイアウト**:
  - `display: grid` を使用し、起点（マウス位置や付箋）を中心に `5x5` 等の目に見えない升目を配置。
  - 中心（`3,3`）は空洞。周囲8マス（第1層レイヤー）としてカテゴリボタンを配置。
  - ホバー時にその外周（第2層レイヤー）のマス目を表示（マス目を結合して `grid-column: span 2` などとすることで長文ボタンにも対応）。
- **利点**:
  - `clip-path` 等を使った「斜めの台形」よりもDOM構築が容易で、境界のクリック判定バグが発生しにくい。
  - 四角形の組み合わせになるため、テキストの折り返しやパディングの制御がCSS標準機能で完璧に行える。

詳細は `01_詳細UI・コンポーネント設計.md` を参照。

## 5. 影響範囲
- `app-ts/src/BoomYack/基本オブジェクト/キャンバス操作/` 配下に「多段グリッドコンテキストメニュー」コンポーネントを新規作成。
- 既存の `円状コンテキストメニュー` との入れ替え、または `自動リサイズ付箋View.ts` での差し替え。

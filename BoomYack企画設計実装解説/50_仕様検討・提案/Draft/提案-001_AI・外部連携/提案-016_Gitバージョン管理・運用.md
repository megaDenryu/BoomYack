# 提案-016: Gitバージョン管理・Obsidianライクな運用

## 1. 現状
- ファイルは単純に上書き保存されるのみ。
- 履歴管理機能はアプリ内にない。

## 2. 問題点・課題
- **破壊的変更への恐怖**: 「大規模なリファクタリング（AIによる分解など）」を試す際、元に戻せないと不安。
- **コラボレーション**: 複数人（または複数エージェント）での編集競合。

## 3. 提案内容
プログラマにとって馴染み深い Git ベースのワークフローを、付箋グラフ管理にも適用する。

### 3-1. 運用イメージ
1. **保存場所**: ローカルのリポジトリフォルダ。
2. **Git管理**: ユーザーは任意のタイミングでコミットする（または自動コミットスクリプト）。
3. **Obsidianライク**:
    - ファイル実体はJSONテキストなので、Gitとの相性は悪くない（ただし行単位diffは見づらい）。
    - フォルダ構造でカテゴリー分け。

### 3-2. アプリ側の対応
- **Reload耐性**: 外部で `git checkout` や `git pull` が行われた際、`watchfiles` (`提案-010`) が変更を検知し、即座に画面を更新する。
- **Diff表示 (将来構想)**: 前のバージョンとのグラフ差分を可視化する機能（追加されたノードを緑、削除を赤で表示など）。

## 4. 影響範囲
- 主に運用ルールの策定。アプリ機能としては `提案-010` (同期など) が前提となる。

## 5. 代替案
- アプリ独自の履歴管理（Undoスタックの永続化）: 実装コストが高いため、Git活用が合理的。

# 提案-016: キャンバス操作のUndo/Redo実装案

## 1. 経緯
Gitベースの履歴管理は高度すぎるため将来構想とし、まずは現実的で即効性のある「一本線の履歴によるUndo/Redo機能」を実装する。

## 2. 実装アプローチ

### 2-1. スナップショット方式 (時間ベース)
差分（コマンド）の保存ではなく、特定のタイミング（アクション終了時）での**モデル全体のスナップショット機能**を実装する。
- グラフ全体のデータサイズはそこまで巨大にならないため、メモリ上に一定数（例：50世代）のJSONオブジェクトを保持するだけでも十分機能する。

### 2-2. 履歴（ヒストリー）リストのUI
- **スクロールカードリスト**: 画面の端（例えば右サイドパネルや時間軸ポップアップ）に、直近の操作履歴をカード形式でリスト表示する。
- **カードの内容**: 
  - `[時間]` 12:35
  - `[概要]` 「ノード追加: "AIの活用について"」
  - ※概要（コミットメッセージ相当）は、発生したイベントの種類（ADD_NODE, MOVE_NODE, AI_EXPANDなど）から自動生成する。

## 3. アーキテクチャ
- `HistoryManager` シングルトン / Contextを作成。
- 状態変更が行われるたびに `HistoryManager.push(currentState, actionDescription)` を呼び出す。
- `Undo` 実行時は `currentState` をポップし、以前のStateをキャンバス全体にリストア（再描画）する。

## 4. スコープ
- このUndo層が実装されれば、後続の「AIによる大規模生成」等も不安なく行えるようになるため、Git管理のような複雑なソリューション導入を遅延・回避できる。

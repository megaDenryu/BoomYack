# 提案-012: UI/UX 設計検討

## 1. ユーザーアクションフロー
1. ユーザーがキャンバス上で起点となる「ノード」を選択する。
2. **マジックアクションボタン**: 選択されたノードの右側に、微かに発光（ネオンパープル）する「✨」ボタンが出現する。
   - 位置: ノードの右端中央から 10px オフセット。
3. **生成開始**: ボタンをクリックすると、ボタンからキャンバス全体に広がるパーティクル（粒子）演出が発生し、AI生成中であることを視覚的に伝える。
4. **ローディング演出**: ボタン自体がスピナーに変化し、バックエンドからのレスポンスを待機する。

## 2. 生成結果のロードとプレビュー (Drafting Mode)
1. AIが生成を完了すると、**仮配置状態（Draft Nodes）** で新しいノードとエッジがキャンバスに出現する。
   - **ビジュアル**: 枠線が破線、背景が半透明（さらにわずかに震えるような微細なアニメーションを持たせることで「確定前」を強調）。
   - **接続線**: 波打つようなアニメーション付きのパス。
2. **レビューバー (Review Bar)**: 画面下部にフローティング形式で出現。
   - `[ AIが3つの提案を生成しました ]`
   - **再生成 (Regenerate)**: 現在の提案を破棄し、同じ条件で再度AIに依頼する。
   - **破棄 (Reject)**: すべての仮配置ノードを消去し、元の状態に戻す。
   - **すべて採用 (Accept)**: 仮配置ノードを正規のノードに変換し、Undoスタックに確定的に積む。

## 3. UIコンポーネントへの要件
- **State管理**: `NodeState` に `Normal | Selected | Draft` の状態を追加。
- **SengenUI準拠**: CSSでのスタイル制御は `data-state="draft"` 等のアトリビュートで行う。
- **パーティクルシステム**: キャンバス上での高パフォーマンスな演出のための簡易エフェクトクラス。
- **フローティングUI**: `ReviewBar` コンポーネント。z-indexを `uiControls` 段に設定。

## 4. 期待される心理的効果
- **「魔法感」**: 単なるメニュー選択ではなく、パーティクルや発光を用いることで、AIが思考を「紡ぎ出している」感覚を演出する。
- **安心感**: いきなりグラフが書き換わるのではなく、一度「下書き」を見せることで、ユーザーのコントロール権を保証する。

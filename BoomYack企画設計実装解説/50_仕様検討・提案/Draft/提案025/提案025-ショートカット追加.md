# 提案025: ショートカット追加 (実装済)

# 機能要求
## Ctrl+vで貼り付ける機能
付箋のテキストエリアにフォーカスしてるとき : 文字の張り付け
キャンバスにフォーカスしているとき: 
- キャンバスでコンテキストメニューにある張り付け機能を呼び出す
	- 今の張り付け機能はクリップボードの文字列がグラフ情報なら付箋グラフを張り付けると思う
	- もし張り付け情報グラフ情報じゃない普通の文字列なら画面中央に付箋を生成して

## redo undo 
Ctrl zで戻る、　Ctrl shift zで進むを実装。
盤面情報をセーブデータの型を使って保持するか、各操作イベントをコマンドオブジェクトにしてコマンドリポジトリに保持するか検討。
対象になる操作は
- 配置物の追加
- 配置物の削除
- 配置物の移動開始
- 配置物の移動終了
- 配置物の変形開始
- 配置物の変形終了
- テキスト編集；ここはそもそもデフォルトでTextArea要素にCtrl zで戻る、Ctrl shift zで進むが実装されている上に仕様も謎なので仕様が競合するのでどうするか検討。しかしここの挙動は壊したくない。もし、テキスト要素のredo undoが発動するときは他のredo undoは発動しないというような仕様にすればうまくいく気がする。
コマンドリポジトリにする方が実装は大変そうだが、パフォーマンスはマシだと思うのでコマンドリポジトリ方式で実装したい。

## コマンドバインド漏れの調査結果と実装計画（2026/02/27追記）

現在、基本的な操作（CanvasViewおよびCanvasItemFactory内での配置物追加、直接の削除、ドラッグ移動、テキスト変更、矢印変更）についてはコマンドリポジトリの実装が完了し、`Ctrl+Z` / `Ctrl+Shift+Z` での Undo/Redo の基礎は組み込まれています。

しかし、以下の「特殊な流れで配置物が増減または変更されるケース」において、コマンドリポジトリへの `executeAndPush` または `push` が漏れていることが判明しました。
既存のコマンドクラス（`配置物追加コマンド`、`配置物削除コマンド`など）を組み合わせることで漏れを塞ぐ計画です。

### 漏れている箇所（要実装）

1. **クリップボードからの貼り付け（テキスト用グラフからの復元）**
   - 箇所: `キャンバスグラフ操作サービス.ts` の `クリップボードから貼り付け` および、その先の `グラフ計算サービス.ts` 内 `テキスト用グラフからキャンバスに配置するサービス.グラフを配置する()`
   - 複数ノードと矢印がまとめて生成されるため、これらを1つの操作としてUndoできるように「マクロコマンド」または「複数追加コマンド」が必要となるか、既存の `配置物追加コマンド` を順次 `push` して対応するか検討が必要です。（※新しいコマンドは極力作らない方針のため、既存コマンドの連続Pushで対応するか、既存の `配置物追加コマンド` が配列を受け取れるように微修正するなど）

2. **AIによる生成と分解**
   - 箇所: `AiOperationService.ts` の `executeGenerate` および `executeDecompose`
   - ここでも付箋や矢印が非同期で追加されますが、`CanvasGraphModel` への直接追加となるためコマンドに記録されていません。`CanvasItemFactory` 経由で生成するようにするか、Service側でFactoryを受け取ってコマンド登録する必要があります。

3. **配置物自体の削除ボタン（on削除）からのルート**
   - 現在 `CanvasItemFactory` では `on削除: this.onDeleteItem` と結びついていますが、もし配置物自身の内部やコンテキストメニューから直接削除が走った場合にコマンド経由になるか確認・徹底が必要です。

### 実装方針
1. 新規コマンドクラスは作成せず、既存の `配置物追加コマンド`、`配置物削除コマンド`、`配置物移動コマンド` などを活用する。
2. 複数の配置物が同時の操作で追加されるケース（ペースト、AI生成）では、連続して `push` すると Undo の粒度が細かくなってしまう問題があるため、どのように Undo の粒度を揃えるか（できれば既存コマンドの配列を受け取るマクロコマンド的なものがないか）確認する。なければ、既存コマンドに配列を渡せるようにする微細なリファクタリングを許容するか検討。
### 実装結果（2026/02/27追記完了）

上記の方針に従い、以下の対応を完了しました。

1. **既存コマンドの配列対応**
   - 新規コマンドを増やさずに対応するため、`配置物追加コマンド` のコンストラクタ引数を `I配置物集約 | I配置物集約[]` で受け取れるように改修しました。これにより、1回の `undo()` 呼び出しで複数の配置物を同時に削除可能になりました。

2. **AiOperationService（AI生成・分解）へのコマンドバインド**
   - `CanvasItemFactory` 経由で生成される際に `AiOperationService` に対し `onCommandPush` コールバックを渡し、`executeGenerate` 実行時（生成された付箋＋接続矢印）や `executeDecompose` 実行時（生成された複数の子付箋＋接続矢印）に、追加された全てのアイテムを配列にまとめて一括で `配置物追加コマンド` を push するよう修正しました。

3. **キャンバスグラフ操作サービス（ペースト機能）へのコマンドバインド**
   - `CanvasView` および `CanvasItemFactory` のクリップボードからの貼り付けイベント発火時に `onCommandPush` を渡し、`グラフ計算サービス` の `グラフを配置する()` が「追加されたノードおよび矢印のリスト」を返却するように改修。それらをまとめて `配置物追加コマンド` に push することで、ペースト時の Undo/Redo の粒度を揃えました。

全対応後、TypeScriptの型チェック（`npm run check:types`）を通過し、Gitコミット（`feat(BoomYack): 提案025 コマンドバインド漏れ対応 (AI生成、ペースト)`）を行いました。

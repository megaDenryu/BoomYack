# 提案-019: フォルダ・ディスカッション駆動型の提案とプロアクティブAI運用

## 1. 概要
提案事項を「1提案＝1フォルダ」の形式に移行したことに伴い、提案内のファイル構成とレビューのフローを厳密に定義する。
また、AIエージェントのレビュー対応に対する「遅延（返信だけで行動しない）」を防ぎ、自律的かつ即座にファイル群を更新していく「プロアクティブな運用」をルール化する。

## 2. 解決する課題
- **タグ・ステータス管理の散逸**: フォルダ全体のメタデータがどこにあるべきか不明瞭。
- **履歴追跡の困難さ**: 概要ファイルにレビューや議論が混在すると、提案の「現在の仕様（結論）」が分かりにくくなる。
- **AIの消極的アクション**: AIがレビューに対して「〜〜を検討します」「提案予定です」と返答文を書くだけで停止し、ユーザーが「じゃあやって」と再度指示する手間（ラリーの無駄）が発生している。

## 3. 提案内容（新ワークフロー定義）

### 3-1. フォルダ構成の標準化（詳細ファイルの分割）
提案は以下のような複数ファイル構成を基本とする。
```
Draft/提案-XXX_タイトル/
  ├─ _概要.md             (全体の要約、結論、最新の仕様。Frontmatterでタグ・ステータスを管理)
  ├─ 01_詳細仕様.md       (必要に応じてUI設計やアーキテクチャなどの詳細を複数ファイルに分割)
  ├─ 02_影響範囲.md       (等々)
  └─ _ディスカッション.md   (ユーザーからのレビューとAIの対応履歴、思考プロセス)
```

### 3-2. ディスカッションファイル駆動（旧称: 案B）
1. ユーザーからのレビューや議論はすべて `_ディスカッション.md` で行う。
2. `_概要.md` は常に最新のクリーンな状態（決定事項のみ）を保つ。

### 3-3. AIのプロアクティブ・アクション（必須要件）
AIはユーザーからのレビューを検知した場合、**絶対に「〜します」という回答文だけで処理を終えてはならない。**
必ず以下の具体的なアクションを同じターン内で「即座に」実行すること。
- **詳細ファイルの生成**: レビューで指摘された不足部分（UI考慮漏れ、アーキテクチャ検討漏れなど）を補うための新しいファイル（例: `01_UI設計.md`）をただちに作成する。
- **概要のアップデート**: 議論の結果、方針が変わった場合は即座に `_概要.md` を書き換える。
- **実装の実行**: 指示があればコードの修正も行う。

## 4. 影響範囲
- 本ルールの承認をもって、BoomYackプロジェクト内におけるAIの標準行動規範として適用する。
- `_目次.md` のフォーマットガイドを本内容に合わせて更新する。

# 提案-023: バグ - 付箋削除時の矢印参照残存問題

## 1. 概要
折れ線矢印で接続された付箋を右クリックメニューから削除した直後に、アプリケーションがエラー（バグ）を起こす問題の修正提案（バグ報告）です。

## 2. 現状のバグ（Issue）
- **再現手順**:
  1. 2つの付箋を折れ線矢印で接続する。
  2. 接続されている片方の付箋を右クリックして出た「削除」ボタンを押す。
  3. アプリケーションがクラッシュする、あるいは矢印が異常な状態になる（バグる）。
  4. その後、別の付箋を矢印に近づけても接続できなくなる。
    - （※矢印を一度動かしてから接続すると直る）

- **原因推測**:
  - 付箋のインスタンス（データ）が削除された後も、それに接続していた「折れ線矢印」側が、削除された付箋への参照（IDなど）を持ち続けている（Dangling Reference）ことが原因と思われる。

## 3. 修正提案（To-Be）
- 配置物を削除するプロセスにおいて、**「自身に接続している矢印（エッジ）の接続情報をクリア（null化）、または該当の矢印ごと同時削除する」**といった依存関係のクリーンアップ処理を追加する。
- グラフ（ノード・エッジ）の整合性を維持するための `CanvasGraphModel` 側でのカスケード削除の処理を実装する。

## 4. 影響範囲
- `app-ts/src/BoomYack/` 内の削除アクション処理
- グラフデータの参照更新ロジック

## 5. 次のステップ
- フロントエンド側の削除イベントのコード（UIからイベント発火後、Modelまでのデータの流れ）を調査・特定し、参照クリア処理を実装してPull Request（変更）を行う。

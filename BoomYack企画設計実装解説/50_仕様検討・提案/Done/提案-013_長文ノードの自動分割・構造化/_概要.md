# 提案-013: 長文ノードの自動構造化・分解機能

## 1. 現状
- 1つの付箋に長文を書き込むと、視認性が悪く、構造が見えにくい。
- 手動で別の付箋に切り出してつなぐ作業は手間がかかる。

## 2. 問題点・課題
- **情報の粒度**: 1ノードに複数のトピックが混在してしまう。
- **再利用性**: 巨大なノードは他の文脈で参照しにくい。

## 3. 提案内容
巨大なテキストを持つノードをAIが解析し、「要約（親）」と「詳細（子ノード群）」に自動的に分解・再構築する機能。

### 3-1. 処理フロー
1. **Analyze**: 対象ノードのテキストをLLMへ送信。
2. **Strategy Selection**: 分解戦略を選択（または自動判定）。
    - `SentenceSplitStrategy`: 文単位で分割（機械的）。
    - `SemanticClusterStrategy`: 意味のまとまりで分割（AI的）。
3. **Generation**: 
    - 親ノード: 元のテキストの内容を表す短いタイトル/要約に置換。
    - 子ノード: 分割された詳細テキスト。
4. **Restructure**: 親ノードから子ノードへエッジを張る。
    - 必要に応じて `originalText` をmetadataにバックアップ。

### 3-2. ドメインモデル設計 (Python Server)
- `DecompositionService`: 分解ロジックを統括。
- `NodeContent`: テキスト操作を担う。
- `IDecompositionStrategy`: 分解アルゴリズムのインターフェース。Strategyパターン。

### 3-3. 設計憲法・適合チェック
- 破壊的な変更を含むため、Undo/Redoまたはバックアップ機能との整合性に注意が必要。

## 4. 影響範囲
- Server: テキスト解析ロジック。
- Client: コンテキストメニュー「このノードを分解・構造化」の追加。

## 5. 課題
- 分解後のレイアウトが爆発的に広がる可能性があるため、自動レイアウト (`提案-015`) との連携が鍵。

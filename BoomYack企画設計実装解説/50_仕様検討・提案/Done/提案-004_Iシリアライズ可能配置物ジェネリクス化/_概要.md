# 提案-004: `Iシリアライズ可能配置物`のジェネリクス化による安全でない`as`キャストの排除

## 1. 現状 (Current State)

`Iシリアライズ可能配置物`は戻り値を共通基底型`配置物データ`に固定している。

```typescript
// I配置物.ts
export interface Iシリアライズ可能配置物 {
    toシリアライズデータ(): 配置物データ;
}
```

実装クラスは適切なサブ型を返すが、呼び出し側ではキャストを強制される。

```typescript
// 配置物情報.ts ← Phase 0リファクタリング後に残存した評尺なキャスト
export class 付箋情報<座標点T extends 配置物座標点> {
    public readonly 配置物データ: 付箋データ
    public constructor(配置物: I配置物集約){
        this.配置物データ = 配置物.toシリアライズデータ() as 付箋データ  // ← 詳細なしのキャスト
    }
}
export class 折れ線矢印情報<座標点T extends 配置物座標点> {
    public readonly 配置物データ: 折れ線矢印データ
    public constructor(配置物: I折れ線矢印集約<座標点T>){
        this.配置物データ = 配置物.toシリアライズデータ() as 折れ線矢印データ  // ← 詳細なしのキャスト
    }
}
```

## 2. 問題点・課題 (Problem / Motivation)

### 構造的な原因
`Iシリアライズ可能配置物`が返り値型を`配置物データ`（基底型）に固定しているため、実装クラスが`付箋データ`や`折れ線矢印データ`を返すことを型システムが認識できない。

- **安全でない`as`キャストが必要になる**：`配置物情報.ts`で`as 付箋データ`
- **型対応がブレるリスク**：将来`まっすぐ矢印集約`等が追加された時、`as`の先が間違いの型になってもコンパイルエラーにならない
- **不正な状態を表現可能にする**：`I配置物集約`を渡しておきながら `付箋データ` を期待するという続の状態は型レベルで排除すべきもの

## 3. 提案内容 (Proposed Solution)

### アプローチ：`Iシリアライズ可能配置物`を型パラメータ化

```typescript
// I配置物.ts — 変更後
export interface Iシリアライズ可能配置物<T extends 配置物データ = 配置物データ> {
    toシリアライズデータ(): T;
}

// I配置物集約は基底型のまま（多娹型判定のためジェネリクス不要）
export interface I配置物集約 extends I選択可能配置物, Iシリアライズ可能配置物<配置物データ>, I衝突判定可能 {
    // ...
}

// サブ型インターフェースで返り値型を絞り込む
export interface I付箋シリアライズ可能 extends Iシリアライズ可能配置物<付箋データ> {}
export interface I折れ線矢印シリアライズ可能 extends Iシリアライズ可能配置物<折れ線矢印データ> {}
```

実装クラス側の変更：

```typescript
// 矢印接続可能付箋Old.ts
class 矢印接続可能付箋Old<T> implements ... , I付箋シリアライズ可能 {
    public toシリアライズデータ(): 付箋データ { ... }  // 戻り値型を明示
}

// 折れ線矢印集約.ts
class 折れ線矢印集約<T> implements ... , I折れ線矢印シリアライズ可能 {
    public toシリアライズデータ(): 折れ線矢印データ { ... }  // 戻り値型を明示
}
```

呼び出し側の変更：

```typescript
// 配置物情報.ts — 変更後
export class 付箋情報<座標点T extends 配置物座標点> {
    public readonly 配置物: I付箋シリアライズ可能
    public readonly 配置物データ: 付箋データ
    public constructor(配置物: I付箋シリアライズ可能){
        this.配置物 = 配置物;
        this.配置物データ = 配置物.toシリアライズデータ();  // ← as不要
    }
}
```

### 3-1. UI/UX設計案（UI Design）
UI変更なし。内部リファクタリングのみ。

### 3-2. 設計憲法・適合チェック (Constitution Check)
- [x] DOM操作を直接行っていないか？→ 履行
SengenUI乖離なし
- [x] LV2コンポーネントを継承していないか？→ 継承変更なし

Vanilla Extract乖離なし

## 4. 影響範囲 (Impact)

| 影響ファイル | 内容 |
|---|---|
| `I配置物.ts` | `Iシリアライズ可能配置物`に型パラメータ追加 |
| `矢印接続可能付箋Old.ts` | `implements I付箋シリアライズ可能` 追加 |
| `折れ線矢印集約.ts` | `implements I折れ線矢印シリアライズ可能` 追加 |
| `配置物情報.ts` | `付箋情報`コンストラクタ引数型を`I付箋シリアライズ可能`に変更し、`as`を削除 |
| `配置物グラフ.ts` | `付箋項目のコンストラクタ`を型安全化 |

`I配置物集約`は基底型のまま維持するため、大规模な波及はない。

## 5. 代替案 (Alternatives)

### A. `as`をそのまま維持
テスト性は低いままだが、Phase 0で排除基調た詳細なしのキャストを残存させる。**獫法行為、不採用**。

### B. `配置物情報`コンストラクタにデータ作成を底たす和別メソッドを渡す
`(配置物: I配置物集約, getデータ: () => 付箋データ)`のように引数を追加する案。呼び出し側が複雑になる。**不採用**。

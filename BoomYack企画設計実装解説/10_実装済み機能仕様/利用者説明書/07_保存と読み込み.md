# 07 保存と読み込み

状態: 草案(オーナー未承認)。索引と語の定義は [[利用者説明書 - 索引]]。

この文書は、ボードの保存先、セーブパネルの操作、保存される条件と保存されない条件、外から更新されたときの振る舞い、データが消える条件を書く。

注記(一時的): 配布版の Jimbo では、画面がパソコンの中のファイルから開かれる。一方、Jimbo のサーバーには、そのような画面からの依頼を受け付ける設定(CORS の設定)が見当たらない。このため、保存先「サーバー」を使う操作が配布版で動くかどうかは確かめていない。また、開発版の Jimbo では、保存先「サーバー」への依頼は、画面を配る開発用のサーバーへ送られ、Jimbo のサーバーへは届かない。この文書のうち保存先「サーバー」に関わる記述は、サーバーへの依頼が届く場合の振る舞いである。オーナーが実機で確かめた後、この注記を外す。

## 自動の保存は無い

- BoomYack はボードを自動で保存しない。BoomYack がボードを保存するのは、利用者が保存の操作をしたときだけである。
- 保存していない変更は、利用者が Jimbo を閉じたとき、または別の保存済みのボードを読み込んだときに失われる。どちらのときも、BoomYack は確認を出さない。
- 利用者が Ctrl+R を押すと、Electron の既定のメニューにより画面が読み込み直され、保存していない変更が確認なしで失われる(画面では未確認。[[90_オーナーの判断事項]] の59番)。

## 保存先

保存先には「ローカル」と「サーバー」の2つがある。

- 保存先「ローカル」とは、Jimbo の画面を表示しているブラウザの部品が持つ保存領域のことである。BoomYack は、保存済みのボード1つを、識別子を含む名前で1件として入れる(内部の名前 N1)。
- 保存先「サーバー」とは、Jimbo の中で動いているサーバーが、パソコンのファイルとして保存する先のことである。サーバーは、保存済みのボード1つを、Jimbo の利用者データのフォルダの中の決まったフォルダに、1つのファイルとして保存する(内部の名前 N2)。
- 保存先「サーバー」のファイルの名前は、識別子から英字・数字・`-`・`_` 以外の文字を取り除いて作られる。このため、日本語だけの識別子は、どれも同じ名前のファイル(名前の部分が空のファイル)を指す。取り除いた結果が同じになる識別子どうしも、同じファイルを指す([[90_オーナーの判断事項]] の39番)。
- MCP が読み書きするのは、保存先「サーバー」の保存済みのボードである。
- セーブパネルの保存先は、Jimbo を起動するたびに「ローカル」から始まる。利用者が保存先を切り替えると、Jimbo を閉じるまでその保存先のままになる。Ctrl+S もこの保存先へ保存する。
- 「サーバー」のボタンは、サーバーを使えるときだけ出る。Jimbo に組み込まれた BoomYack では、「サーバー」のボタンは常に出る。

## 名前と識別子

- BoomYack は、セーブパネルで保存するたびに、セーブパネルの現在名から識別子を作り直す。
- BoomYack は、名前の中の `<` `>` `:` `"` `/` `\` `|` `?` `*` を `_` に置き換え、前後の空白を取り除いたものを識別子にする。結果が空になったときは、識別子を `untitled` にする。
- MCP で作った保存済みのボードは、名前と関係の無い識別子を持つ。ファイルのドロップで入った保存済みのボードも、名前と関係の無い識別子を持つことがある。利用者がそのボードを読み込んで保存したときの振る舞いは、[[90_オーナーの判断事項]] の23番で扱う。
- 起動してから一度も保存も読み込みもしていないボードは、決まった識別子を持つ(内部の名前 N11)。

## 保存されるもの・保存されないもの

BoomYack が保存するものは、次のとおりである。

- ボードの内部名、作った日時、最後に保存した日時
- 表示位置
- すべての付箋の識別子・位置・大きさ・中身・設定(背景色・文字サイズ・文字色)
- すべての矢印の識別子・種類・始点と終点の位置・折れ曲がりの点と中間点の位置・両端がつながっている付箋と接続点

BoomYack が保存しないものは、次のとおりである。

- 表示の倍率
- 選択の状態
- 元に戻す操作の履歴
- 付箋召喚に入力していた文字
- 開いている設定パネルと検索画面

保存される作った日時の扱いは、[[90_オーナーの判断事項]] の20番で扱う。

## セーブパネル

### 開き方と閉じ方

- 利用者がボードのメニューの保存のアイコン(右)を押すと、BoomYack はセーブパネルを開く。セーブパネルの現在名が決まっていないときに利用者が Ctrl+S を押しても、BoomYack はセーブパネルを開く。
- セーブパネルは、ボードの領域の真ん中に、幅 400px の暗い色の枠として出る。セーブパネルの外側は、半透明の黒い覆いで覆われる。
- セーブパネルは、0.2 秒かけて現れる。
- 利用者が右上の「×」を押すか、外側の黒い覆いを押すと、セーブパネルは閉じる。閉じる操作をした時点で、覆いとセーブパネルは操作を受け付けなくなり、0.2 秒かけて薄れて消える。
- セーブパネルが開くたびに、BoomYack は今の保存先の一覧を読み直す。

### 並んでいるもの

セーブパネルには、上から次の順に並ぶ。

1. 見出し「セーブ/ロード」と閉じるボタン「×」
2. 「保存先」と、「ローカル」「サーバー」の2つのボタン。今の保存先のボタンが強調される
3. 「現在のキャンバス名」と、セーブパネルの現在名。現在名が決まっていないときは「（未保存）」と出る。現在名が決まっているときだけ、右に「上書き保存」ボタンが出る
4. 「新規保存」と、名前の入力欄(空のとき「キャンバスの名前を入力...」と薄く出る)と「新規保存」ボタン
5. 「保存データ一覧」と、今の保存先の保存済みのボードの一覧。各行には、保存済みのボードの名前、最後に保存した日時、「json」ボタン、ゴミ箱へ入れるボタン(ゴミ箱の絵)が並ぶ。一覧が空のときは「保存データがありません」と出る
6. 「読込」ボタン
7. セーブパネルのゴミ箱のボタン。セーブパネルのゴミ箱に何かが入っているときだけ出る。ボタンには、入っている数が小さく出る。この数は、保存先「ローカル」と「サーバー」の分を合わせた数である。利用者が一度ゴミ箱の一覧を見ると、BoomYack はボタンの文字を書き換えるときに数の表示を消すので、以後は数が出ない。また、ゴミ箱の中身を実際に消した後も、BoomYack はボタンを更新しないので、ボタンは古い数を出し続け、押すと「ゴミ箱は空です」と出る([[90_オーナーの判断事項]] の58番)

- 一覧の並び順は、保存先が返した順のままである。BoomYack は一覧を並べ替えない。
- 利用者が一覧の行を押すと、BoomYack はその行を選び、強調する。

### 新規保存

1. 利用者が名前を入力して「新規保存」ボタンを押す。BoomYack は名前の前後の空白を取り除く。名前の入力欄で Enter キーを押しても、保存されない。
2. 名前が空のとき、BoomYack はお知らせ「保存名を入力してください」を出し、保存しない。
3. 今の保存先の一覧に同じ名前の保存済みのボードがあり、そのボードがセーブパネルのゴミ箱に入っていないとき、BoomYack はお知らせ「同名のキャンバスが既に存在します」を出し、保存しない。
4. それ以外のとき、BoomYack はボードを入力した名前で今の保存先へ保存する。続いて BoomYack は、一覧で選んでいた行の選択を外し、一覧を読み直し、お知らせ「保存しました」を出し、セーブパネルの現在名を入力した名前にし、名前の入力欄を空にする。

保存先が「サーバー」のときに保存を断られた場合の振る舞いは、下の「サーバーへの保存の規則」に書く。

出典: `ui:基本オブジェクト/キャンバス操作/セーブパネル/セーブパネル保存処理.ts:19-37`

### 上書き保存と Ctrl+S

- 利用者が「上書き保存」ボタンを押すと、BoomYack はボードをセーブパネルの現在名で今の保存先へ保存する。続いて BoomYack は一覧を読み直し、お知らせ「(現在名)を上書き保存しました」を出す。
- セーブパネルの現在名が決まっているときに利用者が Ctrl+S を押すと、BoomYack はボードを現在名で今の保存先へ保存し始め、保存の終わりを待たずに、お知らせ「(現在名)を上書き保存しました」を出す。保存先「サーバー」では、その後にサーバーの結果のお知らせが出る。Ctrl+S では、BoomYack は一覧を読み直さない。
- 保存先「ローカル」では、同じ識別子の保存済みのボードがあれば、BoomYack は確認せずに置き換える。
- 保存先「ローカル」への保存が失敗しても、BoomYack は失敗を開発者向けの記録に書くだけで、利用者には成功のお知らせを出す([[90_オーナーの判断事項]] の42番)。

### サーバーへの保存の規則

- 保存先が「サーバー」のとき、BoomYack は、保存済みのボードを読み込んだときと保存したときにサーバーから受け取った版番号を、識別子ごとに覚えておく。セーブパネルの一覧の「json」ボタンを押したときも、BoomYack はその行の保存済みのボードを読み直し、版番号を覚え直す。
- 次に保存するとき、BoomYack は覚えている版番号をサーバーへ送る。サーバーは、送られた版番号が、サーバーにある保存済みのボードの版番号と同じときだけ保存し、保存するたびに版番号を1つ増やす。
- ただし、サーバーは版番号を照合してから書き込むまでの間、ほかの保存を待たせない。このため、ほぼ同時に届いた2つの保存が両方とも照合を通り、先に書いた方の変更が失われることがある。また、利用者が Ctrl+S をすばやく2回押すと、外で更新されていないのに「ボードは外部で更新されています」と出ることがある(画面では未確認。[[90_オーナーの判断事項]] の57番)。
- BoomYack がその識別子の版番号を覚えていないときは、サーバーはボードを新しいボードとして保存する。同じ識別子(同じファイル)の保存済みのボードがサーバーに既にあるときは、サーバーは保存を断る。
- 保存できたとき、BoomYack はお知らせ「保存しました」を出す。保存を断られたとき、または失敗したときは、BoomYack は次のお知らせを出す。

| 場合 | お知らせ |
|---|---|
| 覚えている版番号と、サーバーの版番号が違う | 「ボードは外部で更新されています (revision (今の版番号))。読み込み直してから保存してください」 |
| 版番号を覚えていないのに、同じ識別子の保存済みのボードがサーバーにある | 「同じ名前のボードが既に存在します。上書きするには先にそのボードを読み込んでから保存してください」 |
| 版番号を覚えているのに、その保存済みのボードがサーバーに無い(外で消された) | 「ボード (識別子) が見つかりません」 |
| 保存する内容が決まった形と合わない | 「保存データが想定形式と一致しません: (理由)」 |
| サーバーとの通信に失敗した。サーバーが失敗の状態番号(413・500 など)を返した場合も含む | 「保存に失敗しました: (失敗の内容)」 |
| 送るボードのデータがサーバーの受け付ける大きさの上限を超えた(上限の値は画面では未確認) | 前の行と同じ「保存に失敗しました: (失敗の内容)」 |

- 通信の失敗のうち、500 番台の状態番号と時間切れのときは、BoomYack は同じ保存を最大3回まで送り直す。時間切れの後に送り直した保存が、版番号の食い違いで断られることがある(未確認)。
- Jimbo のサーバーは、受け付けるデータの大きさの上限を指定していないので、サーバーの部品の既定の上限(約1MiB)が効く。これを超えるボードは、保存先「サーバー」へ一度も保存できない。失敗のお知らせの後に、成功のお知らせも出る(上限の値は画面では未確認。[[90_オーナーの判断事項]] の55番)。

- 版番号を覚えている保存済みのボードが外で消されると、BoomYack は Jimbo を再起動するまで、その識別子へは保存できない。同じ名前で新規保存しても、同じ識別子になるので断られる([[90_オーナーの判断事項]] の43番)。
- 上の表のお知らせは、「新規保存」「上書き保存」「Ctrl+S」「名前の変更」のそれぞれが出すお知らせとは別に出る。このため、サーバーへの保存が断られたときも、「新規保存」「上書き保存」「Ctrl+S」は成功のお知らせを続けて出す([[90_オーナーの判断事項]] の22番)。

### 読み込み

1. 利用者が一覧の行を押して選び、「読込」ボタンを押す。
2. 行を選んでいないとき、BoomYack はお知らせ「読み込むデータを選択してください」を出す。選んだ保存済みのボードがセーブパネルのゴミ箱に入っているとき、BoomYack はお知らせ「削除予定のデータです。復元してから読み込んでください」を出す。
3. それ以外のとき、BoomYack はボードの配置物をすべて取り除き、選んだ保存済みのボードの配置物と表示位置に置き換える。BoomYack は表示の倍率を変えない。続いて BoomYack は、セーブパネルの現在名を選んだ保存済みのボードの名前にし、セーブパネルを閉じ、お知らせ「読み込みました」を出す。

- 読み込む前の変更が保存されていなくても、BoomYack は確認を出さない。
- BoomYack は読み込むときに、配置物を取り除くが、選択は外さない([[90_オーナーの判断事項]] の44番)。
- 保存先「ローカル」で、保存されている中身が決まった形に合わない保存済みのボードを BoomYack が読むと、BoomYack はそのボードを保存先から消す。一覧を読み直すときも、BoomYack は一覧のすべてのボードを読むので、形に合わないボードは一覧を読み直すだけで消える。一覧を読み直すのは、セーブパネルを開いたとき・保存先を切り替えたとき・「新規保存」「上書き保存」「名前の変更」で保存した後・ファイルをボードへドロップしたときである。「json」ボタンを押したときも、その行のボードを読む([[90_オーナーの判断事項]] の41番)。
- 読み込みに失敗したときの振る舞いは [[90_オーナーの判断事項]] の24番で扱う。
- 一覧で選んだ行は、利用者が保存先を切り替えても選ばれたまま残る。切り替えた先に同じ識別子の保存済みのボードがあると、利用者が「読込」を押したとき、BoomYack はその別のボードを読み込む。同じ識別子のボードが無いと、ボードの中身は変わらないまま、セーブパネルの現在名が決まっていない状態(「（未保存）」)になり、お知らせ「読み込みました」が出る([[90_オーナーの判断事項]] の56番)。
- 読み込んだ後に利用者が元に戻す操作をすると、前のボードで消した配置物が今のボードに入ることがある。そのまま保存すると、その配置物も保存される([[90_オーナーの判断事項]] の18番)。
- 保存先「ローカル」に、知らない種類の配置物を持つ保存済みのボードが1つでもあると、BoomYack は一覧を読み直すたびに一覧全体を空にし、「保存データがありません」と出す([[90_オーナーの判断事項]] の54番)。

### 名前の変更

1. 利用者が「現在のキャンバス名」に出ている名前をダブルクリックすると、BoomYack は名前を入力欄に変え、今の名前の全体を選択した状態で、その入力欄をキー入力の受け先にする。セーブパネルの現在名が決まっていないときは、入力欄に変わらない。
2. 利用者が新しい名前を入れて Enter キーを押すか、入力欄の外を押すと、変更が確定する。利用者が Escape キーを押すと、変更をやめる。
3. 新しい名前が空のとき、または今の名前と同じときは、BoomYack は変更をやめる。
4. 今の保存先の一覧に同じ名前の保存済みのボードがあり、そのボードがセーブパネルのゴミ箱に入っていないとき、BoomYack はお知らせ「同名のキャンバスが既に存在します」を出し、変更をやめる。
5. それ以外のとき、BoomYack は次の順に処理する。
   1. ボードを新しい名前で今の保存先へ保存する。
   2. 一覧から古い名前の保存済みのボードを探し、セーブパネルのゴミ箱へ入れる。このとき BoomYack は、「元に戻す」ボタン付きのお知らせ「「(古い名前)」を削除しました」を出す。
   3. セーブパネルの現在名を新しい名前にする。
   4. 一覧を読み直し、お知らせ「"(古い名前)"を"(新しい名前)"にリネームしました」を出す。

- 名前の変更で新しい名前で保存されるのは、保存済みのデータではなく、今ボードにある中身である。
- 保存先「サーバー」で新しい名前の保存を断られても、BoomYack は古い名前のボードをゴミ箱に入れ、現在名を新しい名前に変える([[90_オーナーの判断事項]] の22番)。
- 古い名前のボードは、セーブパネルのゴミ箱に入るだけで、その場では消えない(下の「削除とセーブパネルのゴミ箱」を参照)。
- BoomYack は、古い名前のボードを、今の保存先の一覧から名前だけで探す。このため、利用者が別の保存先から読み込んだボードの名前を変えると、今の保存先にある同じ名前の別のボードがゴミ箱に入る。
- 新しい名前と古い名前から作った識別子が同じになるとき、古い名前と同じ名前の保存済みのボードが2つあるとき、別の保存先から読み込んだボードの名前を変えたときの振る舞いは、[[90_オーナーの判断事項]] の38番で扱う。

### 削除とセーブパネルのゴミ箱

- 利用者が一覧の行のゴミ箱へ入れるボタンを押すと、BoomYack はその保存済みのボードをセーブパネルのゴミ箱に入れ、一覧から見えなくする。同時に BoomYack は、「元に戻す」ボタン付きのお知らせ「「(名前)」を削除しました」を 5 秒出す。利用者が「元に戻す」を押すと、BoomYack はそのボードをゴミ箱から戻し、お知らせ「「(名前)」を復元しました」を出す。
- 利用者がセーブパネルのゴミ箱のボタンを押すと、BoomYack は一覧をゴミ箱の中身(今の保存先の分だけ)に切り替え、ボタンの文字を「← 戻る」にする。ゴミ箱の各行の「↩」ボタンを押すと、BoomYack はそのボードをゴミ箱から戻す。ゴミ箱の中身が空のときは「ゴミ箱は空です」と出る。セーブパネルを閉じると、一覧はゴミ箱でない方に戻る。
- BoomYack は、セーブパネルのゴミ箱の中身を識別子だけで覚えている。このため、保存先「ローカル」でゴミ箱に入れたボードと同じ識別子の、保存先「サーバー」の保存済みのボードも、一覧に出なくなる。逆も同じである([[90_オーナーの判断事項]] の45番)。
- ゴミ箱に入ったボードを BoomYack が実際に消すのは、Jimbo のウインドウが見えなくなったとき(最小化したときや、画面を読み込み直したときなど)か、Jimbo を閉じるときである。保存先「ローカル」のボードは、このとき保存領域から消える。保存先「サーバー」のボードについては、[[90_オーナーの判断事項]] の25番で扱う。
- BoomYack は、セーブパネルのゴミ箱の中身を Jimbo の実行中だけ覚えている。
- 利用者が今ボードに開いている保存済みのボードをゴミ箱に入れても、ボードの中身とセーブパネルの現在名はそのまま残る。この後に利用者が上書き保存か Ctrl+S をすると、BoomYack はゴミ箱に入っている識別子へ保存する。その保存済みのボードは一覧に出ず、保存先「ローカル」では、ウインドウが見えなくなった時点で消える([[90_オーナーの判断事項]] の37番)。

## 外から更新されたとき

- Jimbo の BoomYack は、保存先「サーバー」の保存済みのボードが保存されたり消されたりしたことの知らせを、Jimbo のサーバーから受け取り続けている(内部の名前 N4)。
- 知らせは、保存や削除をした道具が BoomYack の画面か、それ以外(MCP など)かを持っている。BoomYack は、BoomYack の画面からの保存と削除の知らせをすべて無視する。このため、別のウインドウで開いた Jimbo の BoomYack からの保存でも、お知らせは出ない。
- BoomYack は、知らせの識別子とボードの識別子だけを比べ、保存先は比べない。このため、保存先「ローカル」のボードを開いているときでも、同じ識別子の保存先「サーバー」のボードが変われば、お知らせが出る([[90_オーナーの判断事項]] の46番)。
- MCP などがボードと同じ識別子の保存済みのボードを保存したとき、BoomYack はお知らせ「ボードが外部で更新されました (revision (版番号))。セーブパネルから読み込み直してください」を出す。BoomYack がその識別子の版番号を覚えていて、知らせの版番号が覚えている版番号以下のときは、お知らせを出さない。
- MCP などがボードと同じ識別子の保存済みのボードを消したとき、BoomYack はお知らせ「表示中のボードが外部で削除されました」を出す。
- どの場合も、BoomYack はボードを自動で読み込み直さない。外の変更をボードに反映するには、利用者がセーブパネルで保存先「サーバー」に切り替えて、その保存済みのボードを読み込む。このとき、ボードの保存していない変更は失われる。
- 外で更新された保存済みのボードを読み込み直さずに保存すると、上の「サーバーへの保存の規則」のとおり、版番号が違うので BoomYack は保存を断られる。ただし、利用者がその前にセーブパネルの一覧の「json」ボタンを押していると、BoomYack は版番号を覚え直しているので、保存は通り、外の変更を上書きする([[90_オーナーの判断事項]] の40番)。

## データが消える条件の一覧

次のときに、利用者のデータが消える、または置き換わる。どの場合も、BoomYack は確認を出さない。

|---|---|---|
| Jimbo を閉じる | ボードの保存していない変更 | |
| 別の保存済みのボードを読み込む | ボードの保存していない変更 | |
| 保存先「ローカル」で保存する | 同じ識別子を持つ保存済みのボード。名前が違っても、識別子に直すと同じになる名前(例: `a/b` と `a_b`)は同じ識別子になる | 新規保存と名前の変更は、同じ名前のボードがあるときだけ断る |
| 保存先「サーバー」で保存する | 置き換わることはないが、ファイル名が同じになる別の名前(日本語だけの名前どうしなど)のボードは保存を断られる | 断られても成功のお知らせが出る(90の39番・22番) |
| JSON のファイルをボードへドロップする | 保存先「ローカル」の、ファイルと同じ識別子のボード | |

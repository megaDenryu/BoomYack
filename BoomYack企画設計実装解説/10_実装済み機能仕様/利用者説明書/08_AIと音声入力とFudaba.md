# 08 AI と音声入力と Fudaba

状態: 草案(オーナー未承認)。索引と語の定義は [[利用者説明書 - 索引]]。

この文書は、利用者の画面から操作できる外部との連携(AI による生成と分解、音声入力、Fudaba の札)と、MCP から保存済みのボードが変更されたときに利用者に見える振る舞いを書く。

## AI による続きの生成と分解

今の実装では、AI による続きの生成と分解は成功しない(画面では未確認)。BoomYack が依頼を送る宛先が、Jimbo のサーバーに無いためである([[90_オーナーの判断事項]] の26番)。この節には、宛先が応答した場合の振る舞いも含めて、コードに書かれた振る舞いを書く。

### 操作の入り口

- AI の操作は、付箋のメニューの「分解生成」(左上)の第2層にある「LLM分解」「区切り分解」「続き生成」の3つである([[04_メニュー]] を参照)。ボードのメニューの「分解 生成」には、第2層の項目が無い。
- 利用者が AI の操作をできるのは、自由テキストとタイトル付きの付箋である。札参照の付箋では、「LLM分解」「区切り分解」「続き生成」の3つは、押すとメニューが閉じるだけで、ほかには何も起きない。
- BoomYack が AI に送る文字は、[[06_コピーと貼り付けとファイル]] の「付箋を文字にする規則」で付箋を文字にしたものである。
- 自由テキストの付箋の文字が空のとき、BoomYack は何もしない。
- タイトル付きの付箋は、タイトルと本文が両方空でも改行1つの文字になる。このため、BoomYack は AI に依頼を送る。

### 処理中と終わった後の見た目

- AI の処理を待つ間、BoomYack は元の付箋のつかむ枠を緑の点線(マウスを重ねたときと同じ見た目)にする。
- 処理が終わると、成功しても失敗しても、BoomYack は元の付箋のつかむ枠の線を消す。
  - 元の付箋が選択されていたときも、赤の点線が消える。
  - 選択そのものは外れない([[90_オーナーの判断事項]] の30番)。

### 続き生成

- BoomYack は付箋の文字を、Jimbo のサーバーの続き生成の宛先へ送る(内部の名前 N6)。
- 成功すると、BoomYack は次の3つを行う。
  - 元の付箋の本体の左上から右へ 300px の位置に、AI が作った文字を持つ自由テキストの付箋を作る。
  - 元の付箋から、作った付箋への折れ線矢印を作る。
  - お知らせ「AI生成が完了しました」を出す。

### LLM分解と区切り分解

- BoomYack は付箋の文字と分け方を、Jimbo のサーバーの分解の宛先へ送る(内部の名前 N7)。分け方は、「LLM分解」では意味のまとまりごと、「区切り分解」では文ごとである。
- 成功すると、BoomYack は、分けた文字ごとに自由テキストの付箋を作る。
- 分けた文字を上から0番、1番と数えるとき、n 番の付箋の位置は、元の付箋の本体の左上から右へ 300px、下へ (150 + 200 × n)px である。
- BoomYack は、元の付箋から、作った付箋それぞれへの折れ線矢印を作る。続いて BoomYack は、お知らせ「ノードの分解が完了しました」を出す。
- サーバーが要約の文字を返しても、BoomYack は元の付箋の文字を変えない。

### 失敗したときのお知らせ

失敗したときのお知らせは、失敗の起き方で2つに分かれる。

- サーバーが、成功を示す応答の中で失敗を返したときは、次のお知らせが出る。
  - 続き生成: 「AI生成エラー: (失敗の内容)」
  - 分解: 「分解エラー: (失敗の内容)」
- サーバーの応答の状態番号が失敗を示したとき、または通信そのものが失敗したときは、続き生成でも分解でも、「ネットワークエラー: (失敗の内容)」が出る。
- 失敗の内容は、「Error: …」または「TypeError: …」で始まる。例えば、通信そのものが失敗したときは「ネットワークエラー: TypeError: Failed to fetch」になる。
- 今の実装では宛先が無いので、お知らせは「ネットワークエラー: (失敗の内容)」になるとコードからは読める(画面では未確認)。

## 音声入力

- 利用者がボードのメニューか付箋のメニューのマイクのアイコン(左下)を押すと、BoomYack は音声入力を始める。利用者がもう一度押すと、BoomYack は音声入力を止める。
- BoomYack は、ブラウザが持つ音声の聞き取りの機能を日本語で使う。ブラウザがこの機能を持たないとき、利用者がマイクのアイコンを押しても何も起きず、BoomYack はお知らせも出さない。
- 音声入力をしている間、BoomYack は次の2つを行う。
  - ボードの領域の右下に、マイクの絵と「録音中...」の文字を持つ赤い表示を出す。
  - ボードのメニューとすべての付箋のメニューのマイクのマスを赤くする([[04_メニュー]] を参照)。
- 聞き取りが1区切り確定するたびに、BoomYack は確定した文字を、そのとき選択されているすべての付箋に足す。
  - 付箋の文字が空なら、BoomYack は確定した文字をそのまま入れる。
  - 付箋の文字が空でなければ、BoomYack は改行してから確定した文字を足す。
- タイトル付きの付箋では、BoomYack は確定した文字を、本文の末尾に改行してから足す。タイトルと本文が両方空のときは、本文が「改行、確定した文字」になる。タイトルに改行があるときの振る舞いは、[[90_オーナーの判断事項]] の31番で扱う。
- 札参照の付箋と矢印には、BoomYack は文字を足さない。
- 聞き取りがブラウザの都合で終わったとき、利用者が音声入力を止めていなければ、BoomYack は聞き取りを自動で始め直す。
  - 聞き取りが失敗し続けたときも、BoomYack は始め直し続ける。
  - このとき「録音中...」の表示は出たままで、BoomYack はお知らせを出さない。
- 音声入力で足した文字と元に戻す操作の関係は、[[05_キー操作と元に戻す]] の「元に戻す操作の対象にならない操作」に書く。
- 利用者が別の保存済みのボードを読み込んだ後、配置物を選び直さずに音声入力すると、聞き取った文字は、読み込む前に選択していた付箋(今のボードには無い付箋)に入り、失われる([[90_オーナーの判断事項]] の44番)。

## Fudaba の札

BoomYack は、Fudaba の札を、読み取り専用の付箋(札参照の付箋)としてボードに置ける。

### 検索パネル

- 利用者がボードのメニューの付箋のアイコン(上)の第2層「Fudaba 札を 貼り付け」を押すと、BoomYack はその項目を押した位置に検索パネルを開く。すでに検索パネルが開いていたときは、BoomYack は古い検索パネルを閉じてから開く。
- 検索パネルには、見出し「Fudaba札を貼り付け」、閉じるボタン「×」、絞り込みの入力欄(空のとき「タイトルまたはIDで絞り込み...」と薄く出る)、札の一覧が並ぶ。
- 検索パネルが開くと、BoomYack は Fudaba の札をすべて、Fudaba の宛先から1回だけ読む(内部の名前 N8)。読み終わるまで、一覧には「読み込み中...」と出る。
- 一覧の各行には、札のタイトルと、札の種別と状態を示す色付きの小さな表示が並ぶ。タイトルが空の札は「(無題 #(札の番号))」と出る。
- 利用者が絞り込みの入力欄に文字を入れると、BoomYack は、次のどちらかに当てはまる札だけを一覧に残す。BoomYack は入力の前後の空白を無視する。
  - タイトルにその文字を含む札(大文字と小文字を区別しない)
  - 札の番号にその文字を含む札
- 一覧が空になったときは「該当する札がありません」と出る。
- 札を読めなかったときは「一覧の取得に失敗しました: (失敗の内容)」と出る。
- 札を読み終わる前に利用者が絞り込みの欄に入力すると、一覧は「読み込み中...」から「該当する札がありません」に変わる。
- 利用者が一覧の行を押すと、BoomYack は、検索パネルを開いた項目を押した位置に札参照の付箋を作り、検索パネルを閉じる。
- 利用者は、見出しの部分を押して検索パネルを動かせる。
- 検索パネルは、利用者が「×」を押すか行を選ぶと閉じる。利用者がボードの何もない所をクリックしても閉じない。
- 検索パネルは、表示位置の移動や拡大・縮小に付いて動かない。

### 札参照の付箋の表示

- 札参照の付箋を作ったとき、および保存済みのボードを読み込んで札参照の付箋ができたとき、BoomYack は Fudaba の札をすべて読み、その付箋の札の番号に合う札を探す。BoomYack が札を読むのはこのときの1回だけで、札が Fudaba で変わっても、付箋の表示は変わらない。
- 読み終わるまで、付箋には「Fudaba札を読み込み中...」と出る。
- 札が見つかると、付箋には次の3つが出る。
  - 札のタイトル
  - 種別と状態の色付きの小さな表示
  - 担当者。担当者は「担当: (名前)」と出て、担当者がいないときは「担当者未割当」と出る
- 札が見つからないと、付箋には「Fudaba札#(札の番号)」と「この札は見つかりません(削除された可能性があります)」が出る。
- Fudaba と通信できないと、付箋には「Fudaba札#(札の番号)」と「Fudabaサーバーに接続できません」が出る。
- 種別の色は、実装が紫(#5b4a96)、バグが赤(#c9403a)、新仕様が青(#2563a6)、仕様検討が茶(#9a5b16)、タスク分解が紫(#7a4e9d)、記録が薄い紫(#8078a4)、決定が緑(#2f7d5a)で、それ以外の種別は灰色(#757575)である。
- 状態の色は、未着手が灰色(#9e9e9e)、進行中が青(#1e88e5)、完了が緑(#43a047)、ブロックが赤(#e53935)で、それ以外の状態は灰色(#757575)である。
- 利用者は、ボードから札の中身を変えられない。BoomYack が保存するのは札の番号だけである。
- 札参照の付箋の高さは、[[02_付箋]] の「高さの自動の伸び縮み」に書く。

## MCP からの変更

[[07a_保存先と保存の内容]] の冒頭の注記のとおり、保存先「サーバー」への保存の結果は、画面では未確認である。

- MCP は Jimbo の中で動き、12の操作を持つ(内部の名前 N12)。
- MCP の操作のうち次の2つは、日本語の名前の値を受け取る。このため、Claude から MCP を使うときは、この2つの操作が操作の一覧から除かれ、使えない。Claude から使える操作は10個である([[90_オーナーの判断事項]] の51番)。
  - 付箋を1枚だけ足す操作。「背景色」という名前の値を受け取る。
  - 付箋の中身や色を変える操作。「背景色」「文字サイズ」「文字色」という名前の値を受け取る。
- MCP が読み書きするのは、保存先「サーバー」の保存済みのボードだけである。保存先「ローカル」の保存済みのボードと、ボードの保存していない変更は、MCP から見えない。
- MCP が保存先「サーバー」の保存済みのボードを変えても、BoomYack はボードを自動で変えない。ボードと同じ識別子の保存済みのボードが変わったときは、BoomYack はお知らせを出す([[07c_サーバーとのやり取り]] の「外部から更新されたとき」を参照)。
- 利用者が MCP で足した付箋と矢印を見るには、その保存済みのボードを読み込む。
- MCP で足した矢印は折れ線矢印で、始点は元の付箋の右の接続点に、終点は相手の付箋の左の接続点につながる。

### MCP で位置を指定せずに足した付箋

この節を、MCP で足した付箋の位置の正本とする。仕組みは [[90_オーナーの判断事項]] の52番に書く。

- MCP で位置を指定せずに付箋を足したとき、保存済みのボードを編集する BoomYack の部分(MCP と Jimbo のサーバーが使う部分)が、次の規則で位置と既定の値を決める。
  - 付箋が1つも無い保存済みのボードでは、付箋の左上を、描画上の座標で、保存された表示位置と同じ値の点に置く。
  - 付箋がある保存済みのボードでは、最も右の付箋の右端から 40px 右に置き、上端を最も上の付箋の上端に揃える。
  - 既定の大きさは、幅 200px・高さ 100px である。
  - 既定の設定は、背景色 #ffffd0(薄い黄色)・文字サイズ 14・文字色 #000000(黒)である。
- MCP で作った保存済みのボードの表示位置は (0, 0) である。このため、そのボードに最初に足した付箋は、読み込むと付箋召喚と重なる位置に出る(画面では未確認)。
- MCP の操作の詳しい約束は、この説明書の範囲の外である。

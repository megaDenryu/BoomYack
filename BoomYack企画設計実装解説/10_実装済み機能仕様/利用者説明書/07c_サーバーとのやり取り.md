# 07c サーバーとのやり取り

状態: 草案(オーナー未承認)。索引と語の定義は [[利用者説明書 - 索引]]。

この文書は、保存先「サーバー」へ保存するときの規則、保存を断られたときのお知らせ、外部から保存済みのボードが変えられたときの振る舞いを書く。

注記(一時的): オーナーは、配布版(版 1.6.15)で、保存先「サーバー」の一覧が出ることを画面で確かめた。保存先「サーバー」への保存の結果は、画面では未確認である。開発版の Jimbo では、保存先「サーバー」への依頼は、画面を配る開発用のサーバーへ送られ、Jimbo のサーバーへは届かない。この文書のうち保存先「サーバー」への保存に関わる記述は、依頼が Jimbo のサーバーへ届く場合の振る舞いである。

## 版番号の規則

- 保存先が「サーバー」のとき、BoomYack は、サーバーから受け取った版番号を識別子ごとに覚えておく。BoomYack が版番号を受け取るのは、次のときである。
  - 保存済みのボードを読み込んだとき
  - 保存したとき
  - セーブパネルの一覧の「json」ボタンを押して、その行の保存済みのボードを読み直したとき
- 次に保存するとき、BoomYack は覚えている版番号を Jimbo のサーバーへ送る。
- Jimbo のサーバーは、送られた版番号が、サーバーにある保存済みのボードの版番号と同じときだけ保存する。Jimbo のサーバーは、保存するたびに版番号を1つ増やす。
- BoomYack がその識別子の版番号を覚えていないときは、Jimbo のサーバーは、その識別子の保存済みのボードを新しく作って保存する。同じ識別子(同じファイル)の保存済みのボードがサーバーに既にあるときは、Jimbo のサーバーは保存を断る。
- Jimbo のサーバーは、版番号を照合してから書き込むまでの間に届いたほかの保存を、後回しにしない。このため、次のことが起きることがある(画面では未確認。[[90_オーナーの判断事項]] の57番)。
  - ほぼ同時に届いた2つの保存が両方とも照合を通り、先に書いた方の変更が失われる。
  - 利用者が Ctrl+S をすばやく2回押すと、外部で更新されていないのに「ボードは外部で更新されています」と出る。

## 保存できたときと断られたときのお知らせ

- 保存できたとき、BoomYack はお知らせ「保存しました」を出す。
- 保存を断られたとき、または失敗したときは、BoomYack は次のお知らせを出す。

| 場合 | お知らせ |
|---|---|
| 覚えている版番号と、サーバーの版番号が違う | 「ボードは外部で更新されています (revision (今の版番号))。読み込み直してから保存してください」 |
| 版番号を覚えていないのに、同じ識別子の保存済みのボードがサーバーにある | 「同じ名前のボードが既に存在します。上書きするには先にそのボードを読み込んでから保存してください」 |
| 版番号を覚えているのに、その保存済みのボードがサーバーに無い(外部で消された) | 「ボード (識別子) が見つかりません」 |
| 保存する内容が決まった形と合わない | 「保存データが想定形式と一致しません: (理由)」 |
| サーバーとの通信に失敗した。サーバーが失敗の状態番号(413・500 など)を返した場合も含む | 「保存に失敗しました: (失敗の内容)」 |
| 送るボードのデータが、サーバーが受け付ける大きさの上限を超えた(画面では未確認) | 前の行と同じ「保存に失敗しました: (失敗の内容)」 |

この節を、断られても成功のお知らせが出ることの正本とする。

- 上の表のお知らせは、「新規保存」「上書き保存」「Ctrl+S」「名前の変更」のそれぞれが出すお知らせとは別に出る。
- このため、保存を断られたときも、「新規保存」「上書き保存」「Ctrl+S」は、成功のお知らせを続けて出す。
- 「新規保存」では、保存を断られても、BoomYack はセーブパネルの現在名を入力した名前にする。
- 「名前の変更」では、保存を断られても、BoomYack は古い名前の保存済みのボードをセーブパネルのゴミ箱に入れ、お知らせ「「(古い名前)」を削除しました」と「"(古い名前)"を"(新しい名前)"にリネームしました」を出し、現在名を新しい名前にする。
- 保存できたときも、「保存しました」と、操作ごとのお知らせの2つが出る。
- 仕組みと、直すかどうかの判断は、[[90_オーナーの判断事項]] の22番に書く。

## 通信の失敗と送り直し

- 通信の失敗のうち、500 番台の状態番号と時間切れのときは、BoomYack は同じ保存を最大3回まで送り直す。
- 時間切れの後に送り直した保存が、版番号の食い違いで断られることがある(画面では未確認)。
- Jimbo のサーバーは、受け付けるデータの大きさの上限を指定していない。このため、Jimbo のサーバーの部品が標準で持つ上限(約1メガバイト)が効く(内部の名前 N16)。これを超えるボードは、保存先「サーバー」へ一度も保存できない(上限の値は画面では未確認。[[90_オーナーの判断事項]] の55番)。
- 版番号を覚えている保存済みのボードが外部で消されると、BoomYack は Jimbo を再起動するまで、その識別子へは保存できない。同じ名前で新規保存しても、同じ識別子になるので断られる([[90_オーナーの判断事項]] の43番)。

## 外部から更新されたとき

- Jimbo の BoomYack は、保存先「サーバー」の保存済みのボードの更新通知を、Jimbo のサーバーから受け取り続けている(内部の名前 N4)。
- 更新通知には、保存や削除をしたのが BoomYack の画面か、それ以外(MCP など)かが書かれている。
- BoomYack は、BoomYack の画面からの保存と削除の更新通知を、すべて無視する。
  - この BoomYack の画面からの保存では、お知らせは出ない。
  - 別のウインドウで開いた Jimbo の BoomYack からの保存でも、お知らせは出ない。
  - 別のウインドウの BoomYack からの保存でも、版番号は増える。このため、この BoomYack がその識別子の版番号を覚えているときに、読み込み直さずに保存すると、上の「保存できたときと断られたときのお知らせ」の表のとおり、保存を断られる。
- BoomYack は、更新通知の識別子とボードの識別子だけを比べ、保存先は比べない。このため、保存先「ローカル」の保存済みのボードを開いているときでも、同じ識別子の保存先「サーバー」の保存済みのボードが変われば、お知らせが出る([[90_オーナーの判断事項]] の46番)。
- MCP などがボードと同じ識別子の保存済みのボードを保存したとき、BoomYack はお知らせ「ボードが外部で更新されました (revision (版番号))。セーブパネルから読み込み直してください」を出す。
  - BoomYack がその識別子の版番号を覚えていて、更新通知の版番号が覚えている版番号以下のときは、BoomYack はお知らせを出さない。
- MCP などがボードと同じ識別子の保存済みのボードを消したとき、BoomYack はお知らせ「表示中のボードが外部で削除されました」を出す。
- どの場合も、BoomYack はボードを自動で読み込み直さない。外部の変更をボードに反映するには、利用者がセーブパネルで保存先「サーバー」に切り替えて、その保存済みのボードを読み込む。このとき、ボードの保存していない変更は失われる。
- 外部で更新された保存済みのボードを読み込み直さずに保存すると、版番号が違うので、保存を断られる。ただし、利用者がその前にセーブパネルの一覧の「json」ボタンを押していると、BoomYack は版番号を覚え直している。このときは保存が通り、外部の変更を上書きする([[90_オーナーの判断事項]] の40番)。
